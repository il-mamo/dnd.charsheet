# Design review v2

Status: historical revision 2.0 concepts, superseded by design revision 2.1 for startup, Adventure scope and identity. No final owner approval. Player/DM selector is rejected; application is always player-facing. Replaced by Adventure-aware boards in ../review-v2.1/; older images are historical only. Mode: built-in image_gen; use case: ui-mockup. Original generated concepts, no handbook images. Eight representative compositions; all 21 screen/overlay plans appear in DESIGN_SPEC.md section 11.4. Developer metadata and production assets follow approval.

- [Board A](board-a.png): Welcome, Characters, Overview, Guided creation.
- [Board B](board-b.png): Inventory, Spells, Battle, Action resolution.

Requested: 3840x2160 boards, each containing four 16:9 screen concepts representing a 1920x1080 product. Delivered PNGs are review illustrations; no claim of pixel-accurate final geometry. Source: OpenAI built-in image generation, 2026-10-20. Opaque composited boards; do not crop them into production assets.

Visual QA: gothic palette, readable opaque panels, portrait emphasis and major compositions are present. Known deviations: generated navigation, portrait sizing and menu controls vary; welcome/library and wizard contain extra navigation; Overview has wrong tabs; example rules/stats/classes are unverified and sometimes outside scope (including Hexblade in Board B); action drawer invents player/DM mode and dice icons. These are rejected as functional requirements. No dice roller or runtime player/DM mode is planned. Natural dice must be required when the verified rule needs them. Generated copy and values must not be transcribed into code. Written specification governs. Contrast and native UI interaction checks are unrun; documentation diff whitespace check passed.
