## Objective and boundaries

Every application launch presents Adventure selection, including when exactly one Adventure exists. Open Adventure is explicit; list selection only previews. Management remains accessible without a session Adventure. Create an Adventure atomically with a new named incomplete draft or an existing unassigned character; rename, delete while retaining characters, and assign retained unassigned characters to an existing Adventure. Selected Adventure scopes all character activation and portrait editing. Change Adventure clears the active character before any other roster is exposed.

Reuse the implemented character-library panels/cards after explicit Adventure opening. Creation remains the existing named incomplete draft, not a new PHB creation wizard. Transfer between assigned Adventures is Task 2.8. Finder/gameplay, character export, Settings and future guided/existing-entry wizards are not implemented here; do not add misleading enabled actions for these future features. No DM controls. Overview/battle emphasis does not apply to these management-only surfaces.

## Layout contract

Use the existing borderless maximized frame at 1920x1080 / 100%; preserve the 32-DIP title strip and its Backups/minimize/close controls. Backups remains reachable before selection. Reuse the existing 144-DIP banner with page heading Select Adventure, Adventures, or selected Adventure name / Characters. Long banner Adventure names use single-line ellipsis with full name in the tooltip; full name remains available in management detail. In library mode show Change Adventure and Manage Adventures as standard labelled buttons; active-character portrait/name/status remains in the banner. Selection/management has no active-character identity or gameplay sidebar.

Selection and management share a single surface with both sets of labelled controls, accessible before session selection. Selection/management body occupies the existing row below the banner, margin 24. Center a maximum-width 1648-DIP Grid with columns 1040, 24 gap, 584; stretch vertically with bottom margin 24. Panels use SectionPanel: 16 padding, 8 radius, 1-DIP border. Header and command areas remain fixed; lists and long form/detail content scroll locally, never horizontally. Long names wrap within list/detail and do not overlap buttons.

Left selection panel: Select Adventure heading (20), labelled Search Adventures field (40 high), loading/count/empty/error status, vertically scrolling standard ListBox of Adventure names and character counts. List items minimum 64 high, padding 12, 12 bottom gap. Selected item uses Brush.Selection plus visible selected state from the standard selector. Right panel: selected Adventure heading, member portrait/name/incomplete-draft preview list (48-DIP thumbnails, 12 gap, maximum height 160 with local vertical scrolling), then primary Open Adventure. With no preview selection show Select an Adventure to preview its characters. Bottom secondary commands: Create Adventure, Manage Adventures. Search does not activate or silently choose an Adventure.

Management uses the same two-panel geometry. Left heading Adventures with Back to selection and Create Adventure; searchable Adventure list with counts. Right selected detail shows Adventure name input, Rename, member preview, Open Adventure, Delete Adventure. A separately headed Unassigned characters region below the Adventure list shows retained character rows (48-DIP portrait, name, Incomplete draft, Unassigned). Right preview says Assign an Adventure to use this character, includes labelled destination Adventure selector and Assign Adventure. Unassigned previews have no Activate/Resume/Change portrait controls. Management selectors always retain stable IDs internally; names and roster ordinals distinguish duplicate display names, never raw IDs.

Create Adventure uses an explicitly expanded right-panel form (Create Adventure… opens it, Cancel collapses it without clearing input) or a centered 960x640 owned modal with the same tokens: heading Create Adventure; Adventure name (required); first-character choice shown prominently as New draft or Assign [selected unassigned character]; selecting an unassigned row changes that choice and disables the new-name field; Use a new draft instead clears the unassigned selection; Cancel and primary Create Adventure footer. The first-member choices are alternatives, not separate persistence steps. If no unassigned characters exist, show None available and disable that choice. Successful creation refreshes selection and highlights the new Adventure but does not open it implicitly.

Delete and assignment use DS-C12 named confirmation: target Adventure/character and member count; Cancel and explicit Delete Adventure or Assign Adventure. Deletion copy: Characters will be kept without an Adventure and cannot be used until assigned. Assignment names the character and destination. Confirmation may be inline within right detail or an owned modal, but Cancel initially receives focus and no implicit Enter confirmation is permitted. Failure preserves the confirmation target and entered values.

Library mode retains existing 560-DIP new-draft panel, 24 gap and remaining-width three-column card area. Banner shows the Adventure name alongside the active character. Existing 56-DIP header and 64-DIP card portraits, card selection text and draft feedback are reused. New-draft heading includes the selected Adventure context. No characters from other Adventures or unassigned state appear. Management mode cannot leave the old library interactable behind it.

No PHB rules or numeric game constraints are introduced. No resource exhaustion/rest state applies.

## Keyboard and accessibility

Initial focus is Search Adventures after loading, or Create Adventure in a true empty state. Standard ListBox arrow keys select; Open Adventure explicitly activates. Enter in name fields may invoke only the associated non-destructive validated form submission; never delete/assign confirmation. Escape cancels modal/confirmation and restores focus to its invoker. Do not turn Escape into app shutdown or silently discard form input.

Every field has a visible label and AutomationProperties.Name; each repeated action includes its named target. Status/validation use polite live regions, announce meaningful completion/error once, and never announce every filtered member. Preserve visible 2-DIP focus outline and system-color high contrast. Ctrl+Shift+C focuses the current Adventure character list only in library mode; before selection it cannot expose a roster. Ctrl+K remains unavailable until finder exists. Returning from management restores a safe page control; a removed selected item restores to list/search rather than a dead control.
