## Objective and boundaries
Launch an offline WPF application with shared dark gothic resources and truthful database startup feedback. Show “No character selected” persistently. No selectable characters, portraits, class/level, finder, saves, rules, character mutations or functioning destination pages are introduced. Destination names establish the planned information architecture; do not imply they already work. Title bar remains standard Windows chrome with standard move, maximize and close behavior.

## Layout contract
Default window 1280 × 720 DIPs; minimum 600 × 360 DIPs. The shell is a two-row Grid: identity/header Auto, remaining body *. A single vertical ScrollViewer in the body contains a vertically stacked destination region and content panel. No horizontal scrolling. This deliberately compact foundation layout works at narrow effective client sizes; future functional pages may introduce the wide secondary region from DESIGN_SPEC.

Outer canvas uses Color.Canvas. Header uses Color.Surface with 16 DIP padding, 1 DIP bottom divider, wrapping product heading (Georgia Bold 24) and an adjacent or stacked identity label (Segoe UI 14 TextSecondary). Header text: “D&D Character Journal”, “Player’s Handbook 2024”, “No character selected”. Header may wrap entirely into stacked lines at narrow widths; no fixed-height header.

Body padding 24 (16 is acceptable at minimum size), vertical gaps 16. Navigation is a wrapping series of labelled, noninteractive destination chips, each SurfaceMuted with 1 DIP Divider frame, Radius.Control 4, padding 12 horizontal/8 vertical, at least 36 high. Order: Character, Inventory, Spells, Battle, Library, Settings. A persistent sentence immediately beneath reads “Navigation becomes available as features are implemented.” Chips have no hover/pressed/focus state and are exposed as text, not falsely enabled buttons. This is the explicit unavailable state.

Content panel DS-C07 uses opaque Surface, 1 DIP Border frame, Radius.Panel 8, padding 24, heading 24, body 14, helper minimum 12. Width stretches; text wraps. Panel heading: “Your adventure journal”. Body: “Character creation and management will arrive in a later task.” Database startup section below has heading 18 and current status. No large fake stats, sample characters or invented actions. At 1920 × 1080 preserve left-aligned reading hierarchy; constrain inner panel text to 880 DIP maximum width where practical, leaving quiet canvas space. At minimum size all lower content/retry remains reachable by vertical scroll, including at 200% scaling. Window bounds should honor the available work area on launch if smaller than the default.

## State and validation matrix
| Trigger/state | Visible feedback | Enabled actions | Persistence / recovery |
|---|---|---|---|
| Initializing | “Preparing local database…”; optional indeterminate progress bar | Standard window commands only; Retry absent | Off-UI-thread serialized initialization; no character operations |
| Ready | “Local database ready.”; muted body “No character selected.” remains | Standard window commands | No fictitious saved state; actual initializer completion required |
| Failed | “Local database could not be initialized.” plus readable recovery guidance “Retry, or close the app and check access to the local data folder.” | Retry and standard window commands | Preserve existing files; no automatic reset/delete; technical exception/path not required in product text |
| Retry pending | Loading state replaces failure; same operation runs once | No duplicate Retry invocation | Success/failure updates current state |
| Window close | Standard close behavior | Always reachable | No unsaved character state exists |

No form validation, dice inputs, catalogs, confirmations, switching or save error state applies because this foundation introduces none of those operations. Database failure must not resemble an empty-success state or prevent closing the app.

## Keyboard and accessibility
Use standard WPF Button for Retry. Tab/Shift+Tab reaches Retry only when available; keyboard focus outline is 2 DIP Color.Focus inset or adorner without shifting layout. Enter/Space activates a focused Retry; no global Enter action or Escape-to-exit. Initial focus may remain on the window; do not steal focus on asynchronous status updates. If Retry disappears after activation, place focus on the noninteractive shell/window, never an invisible control. Do not bind Ctrl+K or Ctrl+Shift+C until finder/switcher exists.

Define shared Body, Helper, Heading, SectionHeading, secondary Button and panel resources in Desktop Presentation/Design (or equivalent). Centralize all DESIGN_SPEC color tokens as Color plus semantic brushes; centralize listed spacing, corner radii, typography and minimum control size. Normal text 4.5:1, large text and meaningful borders/focus 3:1. Disabled explanations remain fully readable. Hover uses a contrasting surface/border; pressed state visibly differs, keyboard focus is independent. For high contrast map semantic brushes to SystemColors resources and suppress decoration; preserve visible focus and default control semantics. Test switching high contrast while running where feasible; document any restart requirement rather than silently ignoring it.
