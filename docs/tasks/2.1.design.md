## Objective and boundaries
Create a named incomplete character draft and recognize it in the persistent local library after restart. Library is the initial body content. Keep the shell identity `No character selected`; creating or viewing rows does not select an active character. Switching/opening, portraits, editing/deleting, wizard choices, rules and general autosave recovery are later tasks. Existing identity-only records display `Unnamed draft` with the same incomplete status and are never silently renamed in storage. Duplicate names are permitted; each draft retains its own immutable ID. No PHB rules constrain this app-only name field.

## Layout contract
Reuse task 1.4 header, destination strip, page margin, opaque SectionPanel, headings, button styles and all shared semantic colors. Library is visibly the current destination; other unimplemented destinations remain explicitly unavailable.

Reading order within the scrollable page:

```text
Character library                     [page heading]
Create and keep incomplete character drafts here.
Local database: [startup loading/ready/failure with retry]

[New character draft                   section panel]
 Character name (required)
 [single-line name input                            ]
 [name helper or field error]
 [Create draft]
 [creation/saved/failure message]

[Saved characters                      section panel]
 [Loading / empty / error and Retry library]
 [Name, wrapping]
 Incomplete draft
 [separate rows for remaining drafts]
```

Use one column at every width, so list and form remain usable at the shell minimum 600×360 DIPs. Page spacing 24, panel padding 16, field gap 12, panels separated by 16. Form content maximum width 560 DIPs, input fills available width and minimum height 36; create button left aligned and at least 36 high. List fills available panel width, with 12 padding per row and 1 DIP Divider between rows. Names wrap without truncating their accessible content; no horizontal scroll. Use body text for row names, TextSecondary for explicit `Incomplete draft`. Page heading Georgia Bold 24; section heading 18; body 14 and helper minimum 12. At 1280×720 and 1920×1080 DIPs preserve the same hierarchy; extra width is quiet space. Outer body scroll keeps all actions and status reachable at 100%, 150%, 200% scaling/effective client sizes; header does not consume the only scrollable area.

## State and validation matrix
| Trigger/state | Visible feedback | Enabled actions | Persistence / recovery |
|---|---|---|---|
| Database initializing | existing startup status; `Waiting for local database` in library | no create or list retry | no empty-success message |
| Database failed | existing failure/retry; explain library unavailable | initialization retry | preserve name |
| Library loading | `Loading saved characters…` | create may wait for load for simple serialization | no false empty state |
| Empty success | `No saved characters yet. Create your first draft above.` | create | no write |
| Name pristine | `Use 1–80 characters. Duplicate names are allowed.` | create when database/list ready | no write |
| Invalid submit | `Enter a character name.`, `Use 80 characters or fewer.`, or `Use a single line without control characters.` | edit/resubmit | normalized name must contain 1–80 UTF-16 code units after trim; reject control characters anywhere in the original input; preserve input |
| Creating | `Creating draft…`; name and create disabled | no duplicate submission | create exactly one ID in one transaction |
| Create success | `Draft “[name]” saved.`; new row visible | name cleared, ready for next draft | add/refresh row only after durable success; focus name |
| Create failure | `Draft could not be saved. Your name is kept; try Create draft again.` | edit/resubmit | no success or invented row; input retained |
| Library failure | `Saved characters could not be loaded. Retry the library.` | retry; create may remain disabled until list ready | distinguish failed load from empty; preserve input |
| Restart | load all persisted named drafts | same controls | no active character selected |

Validation is an app UX choice, not a game rule. Do not silently truncate input at 80; allow an overlength submission to produce visible validation. Trim only for persisted display value, preserving internal spaces/Unicode. Enter validates the intended form only when focus is in the name field or create button. Escape does not erase the form. No cancellation dialog or resource spending applies. No character switching exists in this task; all operations use explicit IDs internally and cannot mutate an existing draft.

## Keyboard and accessibility
Initial focus goes to the name input once available without stealing focus during later background updates. Tab visits actual controls in visual order, skipping informational rows and unavailable destination labels. Standard text editing remains intact. Preserve shell shortcuts; do not add a library shortcut. Associate persistent label and error with input; status/error feedback uses polite UI Automation live regions. Use visible 2 DIP Focus outlines, meaningful boundaries, and system colors in Windows high contrast. Success/error always includes text. Contrast targets remain 4.5:1 text and 3:1 meaningful boundaries.

None required. Reuse existing dark shell tokens; no new artwork, portrait placeholder or remote resources.
