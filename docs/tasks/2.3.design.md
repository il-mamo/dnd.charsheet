## Objective and boundaries
Import, replace or remove a named character's portrait with a truthful preview before persistence. Owner approved revision 2.2 as the basis for Task 2.3 on 2026-10-20. This correction integrates the approved task/2.2-design-refresh layout at b5cd216 into task/2.3-portraits and adapts portrait entry points to it. Adventure navigation, free-position crop/zoom, generated art and character rules remain outside this task. Capture the immutable character ID and display name on opening; the modal disables underlying character switching until closed.

## Layout contract
Centered, owner-modal WPF dialog, 960×720 DIPs at the supported 1920×1080 / 100% target. Background Surface; normal 1 DIP Border and 8 DIP panel radius. Use 24 DIP outer padding, 16 DIP column gap. Header: Georgia Bold 20, “Portrait — {character name}”, wrapping long names without clipping (up to four lines for the 80-character limit); no IDs or storage paths. Content uses a star-width main column and 240 DIP right preview column, with 16 DIP padding and 12 DIP internal gaps. Header/footer stay visible; explanatory/error text wraps in its region and may scroll locally.

Main column: Choose image button, selected filename text (filename only, ellipsis with accessible full filename), persistent help “JPEG or PNG · up to 10 MiB · up to 4096 × 4096 · up to 16 million pixels”; 400×400 maximum original-image region on SurfaceMuted, centered with Uniform fit; labelled Framing radio group: “Fit whole image” and “Center crop”. Fit is default for newly selected files; crop centrally fills the output square, with no manual positioning. Fit letterboxes with opaque Canvas background; do not stretch or restyle image content. Right column: heading “Preview”, 160×160 square preview and 96×96 circular preview beneath, labelled “Square” and “Thumbnail”. Normalize to 512×512 PNG with opaque #101419 letterbox in Fit mode and central fill crop in Center crop mode. Preview transformations must exactly match the saved normalized PNG; circle clips the same square output without recomposing it.

Footer: left Remove portrait (secondary, Danger text only when shared style supports contrast); right Cancel then Apply portrait (primary), all minimum 40 DIP high with 12 DIP gaps. Footer status immediately above commands announces reading/saving/error/success truthfully. Empty image shows original code-native silhouette and text “No portrait”; existing missing/unreadable asset shows silhouette plus “Portrait unavailable” without losing name or actions. Library uses 64 DIP circular thumbnails; shell identity uses 56 DIP circular thumbnail. Reuse established shell spacing and focus styles.

## State and validation matrix
| Trigger/state | Visible feedback | Enabled actions | Persistence / recovery |
|---|---|---|---|
| No portrait / existing portrait | Fallback or saved image, named target | Choose, Cancel; Remove only with saved portrait; Apply only with pending change | None on open |
| File-picker canceled | Retain prior preview and choice | Prior actions | None |
| Reading | “Reading image…” | Cancel; disable repeated choosing, framing, Apply | No mutation |
| Valid selection | Selected filename and both previews; fit selected | Choose, framing, Cancel, Apply | Pending only |
| Unsupported, corrupt, oversized or dimension-invalid image | Concise selector-adjacent error with allowed limits | Choose, Cancel; preserve previous valid pending preview and its Apply availability | Existing saved image untouched |
| Remove selected | Fallback preview; “Portrait will be removed.” | Choose, Cancel, Apply | Staged; cancel retains existing portrait |
| Applying | “Saving portrait…” | Disable all submission/dismissal and window close during atomic mutation | Capture target ID; prevent duplicate write |
| Save failed | “Portrait could not be saved. Try again.” | Retry via Apply, Choose, Cancel | Keep preview; prior saved reference and image intact |
| Save succeeded | Close modal; updated row/header; named success status | Restore invoking focus | Persist only after managed asset and SQLite reference succeed |
| Missing saved file | Fallback plus “Portrait unavailable” | Choose, Remove, Cancel | Never resolve original arbitrary source path |
| Switching attempted | Modal retains named target; underlying switch blocked | Modal actions only | No cross-character mutation |

File limits are implementation-task policy, not PHB rules: JPEG/PNG only, maximum 10 MiB (10,485,760 bytes), dimensions no greater than 4096 on either side and total pixels no greater than 16,000,000; equality accepted. Reject zero dimensions, decode failures and unsupported formats. Normalize imported orientation where supported and strip source metadata from managed PNG. Preserve visible image identity, use bounded decoding, and release source handles so deleting/moving the original after Apply does not affect the portrait. No rules-derived source references apply.

## Keyboard and accessibility
Initial focus Choose image; standard tab navigation and arrow navigation in radio group. Escape and Cancel discard pending edits except during atomic save; native picker Escape returns to unchanged modal. Enter activates the focused button, never applies solely from radio focus. Restore focus to invoking entry on dismissal. Provide text labels for filename, framing, both previews and validation; error/status use a polite live region and meaningful text rather than color alone. Use shared Segoe UI 16 body, 14 labels, secondary minimum 13; shared palette and 2 DIP focus outline. Honor Windows high contrast with SystemColors for backgrounds, text, borders and focus; image remains user content. Silhouette has no independent meaning beyond adjacent “No portrait”/“Portrait unavailable”.

## Assets
No raster assets. Designer-approved fallback is a simple code-native silhouette: centered circular head above a rounded shoulder/body shape, TextSecondary on SurfaceMuted, preserving 8 DIP inner margin. May instead use the same silhouette as a text glyph only when its installed font rendering is verified; arbitrary emoji are excluded. Developer may implement this exact two-shape vector in reusable XAML: ViewBox 0 0 64 64, head ellipse centered (32,22), radii (10,10); shoulder/body path M12,56 C12,40 20,34 32,34 C44,34 52,40 52,56 Z. Scale uniformly inside the stated margin. Provenance: original geometry described by Graphics Designer for DS-C09, no external licensing or image-generation dependency. Uploaded portraits are user content outside Git; store normalized PNG in managed application data and SQLite reference.
