## Objective and boundaries

Replace the current plain 32-DIP shell title strip with the dark gothic application/menu strip illustrated across `docs/design/review-v2.1/board-b.png`. The strip establishes brand, future menu locations, the current Adventure context, Adventure switching, and window controls without changing the 144-DIP banner or any body content.

The strip exists on every `MainWindow` state. Before an Adventure is explicitly opened, it shows only the brand, placeholder menu labels, center ornament and window controls; it must not imply that an Adventure is active. With an opened Adventure, it additionally shows `Adventure: <name>` and **Change Adventure**. Long names are ellipsized and exposed in a tooltip/accessibility name. **Change Adventure** uses the existing `ReturnToSelectionCommand` and therefore retains Task 2.7 navigation, recovery-drain and active-character clearing behavior.

File, Character and Help are visual placeholders in this revision: render them as noninteractive text, not enabled dead buttons, and exclude them from keyboard traversal and the UI Automation control view. Backups is removed from this strip; its service, dialog and code-behind path remain intact. No Backups replacement route is delivered here. Keep working minimize and close controls. Do not add maximize/restore, menus, drag-to-move, double-click maximize, persistence, rules, banner/body changes, raster artwork or remote fonts.

## Layout contract

Supported viewport remains 1920x1080 at Windows 100%. The top strip occupies the existing first Grid row at exactly 32 DIPs. It spans the window edge-to-edge and uses this visual stack, back to front:

1. Background: vertical gradient from `#162731` at y=0 to `#0B171D` at y=32. Keep it restrained and opaque; no texture or image.
2. Bottom edge: 1-DIP `#66737D` metallic rule at y=31, plus a 1-DIP inner shadow `#05090C` immediately above it. Do not use a rounded outer frame.
3. Content: a three-column Grid with 12 DIP left/right inset. Left is Auto, center is `*`, right is Auto. All content is vertically centered and clipped to the 32-DIP row.

Left group, in reading order:

- Original code-native brand mark, 18x18 DIPs. Use a circular crimson field (`#7C263D`), 1-DIP border `#A83A55`, and a centered simple ivory open-diamond/rune Path no larger than 8x11. It is decorative, not focusable, and must not reproduce an external D&D logo.
- 8-DIP gap, then **DnD.CharSheet** in Georgia Bold 15, `Color.Text`.
- 28-DIP gap, then File, Character, Help at 24-DIP gaps. Each is Georgia Regular 13, `Color.Text`, one line, no underline. They are plain labels in this revision.

Center group:

- Center an original code-native four-point brass ornament on the full flexible middle column, not the whole window. Overall size 16x16; 1-DIP strokes in `Color.Brass`, with a 3x3 central diamond. Decorative only. It must remain visible when the Adventure group is hidden and may shift horizontally as left/right content widths change, matching the reference strip's flexible separator role.

Right group:

- When `ShowCharacterLibrary` is true, show a horizontal Adventure group: label **Adventure:** in Georgia Regular 13 using `Color.TextSecondary`; 8-DIP gap; `AdventureHeading` in Georgia Bold 14 using `Color.Text`, maximum width 260, single line with character ellipsis and full-name tooltip; 20-DIP gap; **Change Adventure**.
- **Change Adventure** is 128x26 DIPs, 1-DIP `Color.Border`, 3-DIP radius, transparent/dark top-bar background, Georgia Regular 13, `Color.Text`, horizontal padding 12. Hover uses `Color.Selection`; pressed uses `Color.Canvas`; focus is the shared 2-DIP `Color.Focus` inset ring. Do not reuse the global 40-DIP minimum-height button style unchanged; create a narrowly scoped top-bar button style.
- 12-DIP gap follows the Adventure group when visible.
- Window controls are always present in the order Minimize, Close. Each is 40x32 DIPs, square, borderless and transparent at rest. Glyphs are Segoe UI Symbol or Segoe UI, not Georgia: minus `U+2014` at 14 DIPs and close `U+00D7` at 20 DIPs. Minimize hover uses `Color.Selection`; Close hover uses `Color.DangerFill`; pressed uses `Color.Canvas`; both use the 2-DIP `Color.Focus` inset ring. There is no maximize button and no gap reserved for one.

The left and right groups must never overlap at the supported viewport. If a pathological Adventure name exceeds its maximum, only that value ellipsizes. No top-bar content wraps or scrolls. Retain the existing 144-DIP second row and body row without shifting their internal layout.

Shared resource additions may be limited to `Color.TopBarTop`, `Color.TopBarBottom`, `Color.TopBarRule`, `Color.TopBarShadow`, `Brush.TopBar`, and scoped `TopBarButton` / `WindowChromeButton` styles. `Brush.TopBar` is the specified gradient in normal mode. `Theme.Apply` must replace it with a solid `SystemColors.WindowBrush` in Windows high contrast; the new top-bar colors must not remain as decorative gradient stops in high contrast. Reuse existing Text, TextSecondary, Border, Selection, Canvas, DangerFill, Focus and Brass resources rather than duplicating them.

## State and validation matrix

| Trigger/state | Visible feedback | Enabled actions | Persistence / recovery |
|---|---|---|---|
| Startup / no opened Adventure | Brand, placeholder labels, ornament, minimize and close; no Adventure label/name or Change Adventure | window controls only | none; no Adventure is inferred |
| Opened Adventure | `Adventure:` plus current name and Change Adventure | Change Adventure and window controls | display reflects existing selected session only |
| Long Adventure name | value ellipsizes at 260 DIPs; full name available by tooltip and accessible name | unchanged | none |
| Adventure navigation busy/unavailable | existing command state disables Change Adventure; disabled text/border remain readable | window controls remain | existing navigation/recovery behavior only |
| Placeholder selected by pointer/keyboard | no hover, focus or action because it is text, not a control | none | none |
| High contrast | solid system Window background; system WindowText, Highlight/HighlightText and focus colors; decorative ornament may remain only if system-colored and nonessential | unchanged | none |
| Close blocked by modal/pending work | retain existing close guard with no new visual state required in this task | existing behavior | existing drain/modal protection |

No loading, input validation, character-switch or duplicate-submit states apply: the strip performs no new mutation and binds only to existing shell state/commands.

## Keyboard and accessibility

The placeholders do not create misleading dead Tab stops. Existing page focus order is not otherwise reordered. When reachable, top-bar actionable order is Change Adventure (only when visible/enabled), Minimize, Close. Space/Enter invoke the focused standard Button. No new access keys or shortcuts are introduced. Escape has no top-bar effect. After Change Adventure, existing Task 2.7 focus behavior owns the destination; minimize/restore follows Windows behavior; cancelled/blocked close leaves focus unchanged.

All actionable controls keep visible 2-DIP focus outlines without layout shift. Expose the window control names given above. Mark ornaments decorative and exclude their Paths from the accessibility tree. The full Adventure name must be exposed even when visually trimmed. Normal text and controls use existing contrast-qualified semantic tokens. High contrast must be checked with the runtime `Theme.Apply` mapping; a normal-mode gradient is not acceptable behind system WindowText in that mode.
