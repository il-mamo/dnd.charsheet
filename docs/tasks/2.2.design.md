## Objective and boundaries
Activate an existing persisted incomplete draft from the library and immediately recognize whose read-only details are displayed. The library remains the current destination; activation does not pretend that a playable character sheet exists. Selection is session-only: restart returns to `No character selected`. Creating a draft does not activate it. No editing, portraits, rules, resource spending, persistence writes on activation or new navigation destinations. The new-draft name input is global form state and survives switching unchanged. Immutable CharacterDraft ID identifies the selected record; duplicate names never identify a command target.

## Layout contract
Compact identity contract: keep read-only details compact in the persistent shell: `Active: [name] — Incomplete draft` and full `ID: [ID]`. No additional Current character panel is required. The empty shell says `No character selected` and `Select a saved draft below.` (or `Create a draft below to begin.` when the library is empty). Switch character and Ctrl+Shift+C focus the first row action and bring it into view; with no row, focus/scroll the new-draft name input instead of the saved heading. Creation completion restores name-input focus only while focus is still within the new-draft form, preserving focus after switching. These are compact reuse decisions under DS-C01, not a new screen.

Busy empty-library exception: while creating the first draft the name input is disabled by the existing create contract. Invoking Switch character/shortcut then preserves current focus until an enabled row/input exists; it makes no state change. Existing `Creating draft…` feedback explains the wait. Equivalent clear copy (`Active character:`, `Character ID:` and `Activate a saved draft below.`) is accepted; status can occupy its own compact header line.

Reuse the existing single-column library, opaque SectionPanel, destination strip, shared secondary Button and all task 2.1 spacing. Do not add artwork or a new token source. Add these regions in reading order:

```text
Persistent shell
  Active: [name, wrapping] ? Incomplete draft / No character selected
  Character ID: [full immutable ID, wrapping; shown when selected]
  [Switch character]

Existing library introduction and database status
Existing New character draft form      [unchanged]
Saved characters
  [name, wrapping]
  Incomplete draft [· Active when selected]
  Character ID: [full immutable ID, wrapping]
  [Activate] / [Active]                [secondary Button]
```

Panel padding 16 DIPs, panel separation 16, row padding 12, existing 1 DIP Divider. Row action follows the identity text with an 8 DIP gap, left aligned, minimum height 36. Use SectionHeading 18 for the existing panel titles and body 14 for fields; secondary text is at least 12. Full IDs remain discoverable and wrap without horizontal scrolling. Names and shell identity wrap; no truncation as the only representation. Keep shell content compact and allow its identity region to scroll vertically if unusually long text would consume all available height; the body must retain reachable scroll space at minimum window size. All body content remains in the existing vertical ScrollViewer at 600×360, 1280×720 and 1920×1080 DIPs and effective client sizes at 100/150/200% scaling. No fixed-width detail column is needed.

| Region/control | Component and tokens | Data / format | Command / behavior | Focus order / accessible name |
|---|---|---|---|---|

Current row button may stay enabled as an idempotent `Active` command so keyboard focus remains stable. Do not disable a focused button or move focus on ordinary activation. Active text is mandatory; color is optional and must use shared tokens. Existing create form and feedback retain task 2.1 semantics and initial-focus behavior.

## State and validation matrix
| Trigger/state | Visible feedback | Enabled actions | Persistence / recovery |
|---|---|---|---|
| Initial / restart | No character selected; header explains activation | Switch affordance; existing form when ready | No restored selection |
| Library loading / failed / empty | Existing distinct loading, retry and empty feedback | No activate rows; Switch focuses new-draft name input | No selection invented and no write |
| Activate valid loaded ID | Shell identity/details change atomically; target row shows Active | Standard row and form controls | Synchronous local selection; no repository save |
| Duplicate display names | Full ID distinguishes each row, accessible command and selected identity | Each row targets its own ID | No name lookup or cross-write |
| Rapid A/B/A activation | Final shell identity/details and Active marker all identify A | No confirmation dialog | No delayed selection callback or stale details |
| Stale/unknown command target | Retain current identity and details | Existing valid commands remain available | Ignore unknown ID; never display an unlisted supplied object |
| Create while selection exists | Existing creation feedback; current identity retained | Existing creation serialization | Creation persists only the new draft; no autoactivation |
| Switch with typed new name | Typed input and existing validation remain unchanged | Form remains usable | Input is global and never saved into selected draft |

No character-edit validation, confirmation/cancel dialog or rule-derived numeric input applies. Escape leaves selection and typed form text intact because this is an inline surface, not a dialog. Selection is not a save event and must not display a false Saved message.

## Keyboard and accessibility
Ctrl+Shift+C invokes the same switch-focus behavior as the shell button; no collision with existing shortcuts. Bring the first row action into view before focusing it. If no actionable row exists, focus the new-draft name input, bringing the form into view. Tab order is shell Switch character, existing startup retry if shown, name input, Create draft, library retry if shown, row activation buttons. Standard Enter/Space activate focused buttons; Enter in the name input retains its existing create behavior. Activation retains focus on its row button and announces active identity politely. Initial focus remains the task 2.1 name input; do not steal it after background list updates. All IDs are available to UI Automation without requiring hover. Retain shared 2 DIP focus, system-color high contrast, 4.5:1 text and 3:1 meaningful boundary targets. Active selection has explicit text independent of hue.

- DES-2.2-04 (R01): typed new-draft input survives switching; creating C retains the selected A; restart loads drafts but has no active selection.
- DES-2.2-05 (R03): current details remain explicitly Incomplete draft; no invented class, level, rules or portrait is displayed.

- DES-2.2-07: long names and IDs wrap; actions/current identity remain reachable at minimum, reference sizes and 100/150/200% scaling; high contrast retains legible identity, explicit Active marker and focus.
