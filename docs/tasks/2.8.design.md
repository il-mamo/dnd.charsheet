## Objective and boundaries

Move one captured character from its captured source Adventure to a chosen existing destination, after explicit confirmation. Open from a scoped character card or Adventure management member row using a labelled Transfer… button. Management can transfer without opening an Adventure. Keep the original session Adventure selected after success; clear its active character only if that character moved. No implicit activation in the destination. Assignment of unassigned characters remains the existing 2.7 flow. No history screen or speculative history storage; P07 recording remains deferred until that facility exists. No character deletion, artwork generation, PHB rules or new gameplay surface.

## Layout contract

Use an owned, centered, non-resizable 960×640-DIP modal at the supported 1920×1080 / 100% display. Match existing modal chrome and shared dark theme; do not introduce separate system colors or decorative artwork. Use Surface background, Border 1 DIP, radius 8, padding 24. Content Grid rows: heading Auto, identity Auto, central picker/preview *, status Auto, footer Auto. Headings/footer remain visible; central content scrolls vertically if long names or errors require space. No horizontal scrolling.

Reading order: Transfer character heading (Georgia Bold 20); 64-DIP circular managed portrait/fallback beside wrapped character name and Incomplete draft; read-only From Adventure name and current member count; To Adventure (required), search box, destination list; preview; consequence; live status; footer Cancel / Transfer character. Identity row gap 16; section gap 16; field gap 8–12. Body 16, labels 14, secondary minimum 13. Names wrap and remain fully available without exposing raw IDs. Picker list has at least 120 DIP height, uses remaining central space, and scrolls locally. Footer aligns buttons right, Cancel then primary action with 12-DIP gap and 40-DIP minimum height.

Preview shows named source and destination with current → after-transfer character counts. Source count decreases by one; destination increases by one. Label them Preview so counts do not imply saved changes. Always show “Moves this character to the selected Adventure.” for a valid choice. No destination is preselected. Exclude the source by stable identity, not its display name. Preserve exact names; duplicate Adventure names remain separate rows, with member counts and stable list order as secondary context. Do not invent user-facing aliases or show internal IDs.

## State and validation matrix

| Trigger/state | Visible feedback | Enabled actions | Persistence / recovery |
|---|---|---|---|
| Initial/loading | “Loading Adventures…”; identity/source remain visible | Cancel; no confirm | No writes; distinguish load from empty |
| No destinations | “No other Adventures. Create one in Adventure management first.” | Cancel | No implicit creation |
| Search no matches | “No matching Adventures.” | Edit/clear search, Cancel | No writes |
| Destination not selected | “Choose a destination Adventure.” | Picker/search/Cancel | Confirm disabled |
| Valid preview | Both names and before/after counts, consequence text | Transfer character / Cancel | Selection changes nothing |
| Last source member | “This is the last character in this Adventure. Delete the Adventure in management to keep its character unassigned, then assign it elsewhere.” | Manage source Adventure / Cancel | Transfer disabled; do not silently delete |
| Pending | “Transferring [character]…” | No repeat, picker edit, cancel, title-close or session navigation | Captured IDs remain fixed; preserve pending recovery before mutation |
| Stale source / missing destination | “Transfer could not be confirmed. Refresh and check the Adventures before trying again.” | Cancel; safe explicit reload/reopen | Original transaction changes nothing; never rebind target silently |
| Failure | Clear failed status; retain selected destination and identity for review | Cancel; explicit retry only when source/destination revalidated | No successful claim before commit; if outcome is uncertain, check membership before offering repeat |
| Success | Named result in parent status; close modal after successful reconciliation | Normal actions after refresh | Refresh rosters/counts, deactivate moved active character, stay in source session; refresh failure must not offer the committed transfer again |
| Cancel/close | Dismiss without success feedback | Parent resumes | No membership writes; restore invoking focus |

Counts are nonnegative integer character counts, including drafts, with no dice/units/culture-dependent entry. Last-member and membership checks must also occur transactionally at confirmation; the preview is not authority. Resource exhaustion/reset and missing private rules catalog are inapplicable because this task changes membership only.

## Keyboard and accessibility

Use standard accessible WPF controls and shared focus visuals. Focus Cancel initially. Tab follows the table; Shift+Tab reverses, focus remains within the modal. Arrow keys select list rows without transferring. Escape/window-close cancel only while not pending. Enter activates a deliberately focused button; search/list Enter must not unexpectedly commit. Restore focus to the invoking Transfer button when retained; after successful removal focus the source roster heading or management member list. Live-setting Polite announces loading, blocked, failed and saved status; name both character and Adventures in confirmation context. Error reasons are visible text, not color or tooltip alone. Reuse existing high-contrast resources. Verify text/control focus contrast and clipping at the supported display; no smaller-window or alternate-scale acceptance is introduced.
