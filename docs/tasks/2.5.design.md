## Objective and boundaries

Create a complete backup of currently implemented characters, managed portraits and draft recovery; inspect and explicitly restore a validated backup while retaining a safety copy. This is an application-wide action, so identify the target as **All characters**, rather than presenting it as a mutation of the active character. Preserve the shell identity behind the modal. Adventure membership, portable character export/import, custom-item editing, settings tabs and backup catalog management are deferred. No new artwork or general settings screen is required.

## Layout contract

Add a text **Backups** secondary button to the shell title strip, before Minimize and Close, with 12 DIP separation from window controls. Keep the active identity region unchanged. Entry remains reachable after startup failure so a valid backup can recover the application. Drain pending writes before opening; if draining fails, explain the blocker and retain state. A failed safety snapshot still blocks destructive restoration. Current character count may be labelled unavailable when startup failed; do not present a false zero.

Open a standard owner-modal, centered, non-resizable 800×680 DIP window titled **Backups**, at the supported 1920×1080 / 100% display. Use Surface background, Text foreground, 1 DIP Border outline, 8 DIP panel radius and 24 DIP padding. Grid rows are heading / scrollable content / fixed footer; content has 16 DIP separation from heading and footer. Use existing shared button/panel styles, 40 DIP minimum control height, 12 DIP button gaps, 16 DIP body and 14 DIP secondary copy. Heading is Georgia Bold 20. Text wraps, filename paths may wrap and content scrolls vertically without moving footer actions.

Content reading order:

1. Heading **Backups**, scope line **All characters, portraits and draft recovery.**
2. Section **Create backup**, explanatory line **Save a copy of your current data.**, and **Create backup.** button using the existing primary style. Open the native Save file dialog for the versioned ZIP archive. Do not expose database or manifest internals.
3. A 24 DIP gap, then section **Restore backup**, explanatory line **Replace current data with a saved backup.**, and **Choose backup.** secondary button. Native Open file dialog accepts the supported archive.
4. On validation success, a SurfaceMuted preview panel (16 DIP padding, 1 DIP Border, 8 DIP radius): filename, backup creation date/time with local timezone, then labelled incoming counts for **Characters**, **Portraits**, **Draft recovery**, and a clearly separate **Current characters to replace** count from the loaded library, or **Current characters unavailable** after startup failure. A recovery count can be 0 or 1. Show incoming character names in a wrapping or locally scrolling list to identify the archive. Do not invent current portrait/recovery counts.
5. Always-visible warning within the valid preview: **Restoring replaces all current characters, portraits and draft recovery. A safety backup will be saved first.** Use Warning text on opaque SurfaceMuted; meaning is conveyed by words. No merge implication or internal IDs.
6. One wrapping status/error area below the relevant section, announced politely. After creation show **Backup saved.** and destination. After restore show **Backup restored. Safety backup saved to:** and destination, with refreshed shell/library state. A readable full path is appropriate here because it identifies the recovery file, rather than an implementation diagnostic.

Footer has **Cancel** on the left of **Restore backup** at the right edge. Restore uses DangerFill / OnAccent and a meaningful border; disabled until validation and preview complete. Cancel becomes **Close** after successful restoration. No default destructive button.

## State and validation matrix

| Trigger/state | Visible feedback | Enabled actions | Persistence / recovery |
|---|---|---|---|
| Initial, including no characters | Scope and the two sections; no invented empty backup list | Create, Choose, Cancel; Restore disabled | No writes |
| Native chooser cancelled | Existing status/preview retained | Prior enabled actions | No data/archive mutation |
| Validating | Validating backup.; clear old preview before new selection | Cancel/close only if cancellation is safe; duplicate actions blocked | No live-data mutation |
| Unsupported, corrupt or incomplete file | This backup could not be opened. Choose a valid backup.; concise specific reason when useful | Create, Choose, Cancel; Restore disabled | Current state unchanged; discard stale preview |
| Valid preview | Date, exact incoming counts and current character count and replacement/safety warning | Create, Choose, Cancel, Restore | Validation alone does not restore |
| Creating / restoring | Creating backup. / Restoring backup. | All conflicting actions disabled; prevent close during atomic replacement | Serialize with existing writes; no duplicate submission |
| Creation fails | Backup could not be saved. Try another location. | Retry via Create, Choose, Cancel | Current state retained; incomplete export cannot appear successful |
| Safety-copy creation fails | Safety backup could not be saved. Current data has not been replaced. | Retry/Choose/Cancel | Block replacement |
| Restore fails | Backup could not be restored. Your previous data is retained.; identify safety file when available | Retry/Choose/Cancel after recovery is complete | Preserve or recover prior state; never show success |
| Restore succeeds | Explicit completion plus safety location | Close; permit further action only after state refresh | Clear stale active selection and reload library/recovery state |

No search, rules catalog, battle mode or character switch controls occur within this modal. Background character switching and editing remain inaccessible throughout. Restore targets the application snapshot, never an implicitly selected character. Any pending draft recovery must be durably settled before snapshot/preview, or the operation must explain the blocker.

## Keyboard and accessibility

Initial focus is Cancel. Trap Tab within modal using normal WPF dialog behavior; visual reading order defines traversal. Escape cancels only unconfirmed/nonbusy work and returns focus to Backups. Enter activates only the focused control; never assign Restore as IsDefault. Busy close protection must cover Escape, native close and shell close. Return focus to Cancel after a file chooser/validation completes, so a subsequent Enter cannot accidentally replace data. Native chooser cancellation returns to its invoking button. Status text uses a polite live region. Controls have visible labels and shared 2 DIP Focus outlines; use system colors in high contrast, with error and warning words retained. No new shortcut is required.

- DES-2.5-02: Initial focus is Cancel; keyboard reaches Create, Choose, Cancel and Restore in order; Escape cancels without mutation and restores focus. Enter cannot implicitly restore.
- DES-2.5-03: Selecting a valid backup shows creation time, incoming counts and current character count and explicit replacement/safety consequence before Restore is enabled. Invalid files clear stale preview and cannot be restored.

- DES-2.5-05: Successful restoration refreshes the library and draft recovery, clears stale selection, and reports safety-copy location. Failure is actionable, preserves prior state and never displays success.
- DES-2.5-06: Shared focus, contrast and high-contrast states remain readable; status is exposed to UI Automation. Native rendering, keyboard and assistive announcements require execution evidence.
