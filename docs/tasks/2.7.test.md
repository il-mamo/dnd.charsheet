## Reproducing the standalone harness

Create `artifacts/task27-test/Task27Harness.csproj` with the following contents (the artifact directory is ignored):

```xml
<Project Sdk="Microsoft.NET.Sdk">
  <PropertyGroup>
    <OutputType>Exe</OutputType>
    <TargetFramework>net10.0-windows</TargetFramework>
    <UseWPF>true</UseWPF>
    <ImplicitUsings>enable</ImplicitUsings>
    <Nullable>enable</Nullable>
    <EnableDefaultCompileItems>false</EnableDefaultCompileItems>
  </PropertyGroup>
  <ItemGroup>
    <Compile Include="../../docs/tasks/2.7.test-harness.cs" />
    <ProjectReference Include="../../src/DnD.CharSheet.Desktop/DnD.CharSheet.Desktop.csproj" />
    <ProjectReference Include="../../src/DnD.CharSheet.Infrastructure/DnD.CharSheet.Infrastructure.csproj" />
  </ItemGroup>
</Project>
```

Run from repository root with `DOTNET_CLI_HOME` set to `.local/dotnet`. Restore/build the runner once with `dotnet run --project artifacts/task27-test/Task27Harness.csproj -c Release -p:NuGetAudit=false` if offline audit metadata is unavailable; subsequent runs use the final `--no-restore` command above. This disables only the runner invocation's network audit, not source dependency checks. The harness creates isolated temporary SQLite/journal data and removes its own temporary directory on completion.
