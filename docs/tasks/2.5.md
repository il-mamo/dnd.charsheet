## Storage behavior and limitations
Version-1 ZIP manifest accepts only schema 3, exact supported tables/constraints, normalized named drafts, referenced PNG files and bounded version-1 recovery journal. Earlier/newer schemas require a compatible application; migration/import and Adventures remain deferred. ZIP paths/entry counts/per-file and total expanded sizes are bounded. Restore uses privately staged validated bytes, creates a verified safety ZIP outside live data, and swaps sibling directories with rollback/startup recovery. Single-session ownership and drained Desktop writes are prerequisites. Corrupt current data blocks safety backup and therefore restore; no live bytes are changed, requiring manual recovery. Orphan portraits and migration snapshots are excluded from backups. Atomicity is at whole live-data directory rename boundaries; startup resolves an interrupted first rename to the previous data. OS/power-loss durability beyond flushed files and platform rename behavior is unverified.
